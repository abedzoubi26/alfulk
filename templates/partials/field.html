{% comment %} One bound form field: label, help text, errors and the control itself. Expects `field`. The accessibility wiring is deliberately left to Django 5's BoundField, which already adds `aria-invalid="true"` when the field has errors and an `aria-describedby` pointing at `_helptext` and `_error`. This template's job is to emit elements carrying exactly those ids. Reimplementing the attributes here would mean two sources of truth for the same association. Help text is escaped, deliberately unlike Django's own field template, which applies `|safe`. This partial is the baseline every screen inherits, and the help text those screens want carries user-controlled values -- an email address, a display name. Escaping by default means a field cannot become an HTML injection sink by accident. A field that genuinely needs markup opts in at the point it is defined, with `format_html()` or `mark_safe()`, where the decision is reviewable.
